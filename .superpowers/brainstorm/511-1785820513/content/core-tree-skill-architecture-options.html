Core Tree 細項 Skill：三種落地架構

五個業務能力已確認。現在決定它們如何被發現、呼叫、維護，以及如何約束不同語言的實作。

✓
已確認：驗證輸入、判定內容差異、解析邏輯對應、分類 A／B／C、建立交付目錄。
方案 1

父 Skill 內的章節模組

五項規格都放在 aras-compare-core-tree 的 references 內，不建立新的頂層 Skill。

aras-compare-core-tree
↓ 內部 references
能力 1
能力 2
能力 3–5
優點檔案集中、頂層 Skill 數量少。
代價同事難以直接指定細項；AI 發現能力較弱。
方案 2 · 建議

五個獨立 Skill＋父 Skill 協調

每項都是可直接呼叫的頂層 Skill，自有完整契約與驗收案例；父 Skill 只負責組合及狀態管理。

aras-compare-core-tree
↓ 明確調用
Skill 1
Skill 2
Skill 3–5
↓ 同一驗收契約
C# ／ Python ／其他實作
優點最符合直接呼叫、獨立維護與跨語言重建。
代價Skill 數量增加，需治理命名與共用詞彙。
方案 3

一個能力入口＋模式參數

新增一個 core-tree-capabilities Skill，以 mode 選擇五項能力；父 Skill 與同事都呼叫同一入口。

aras-compare-core-tree
↓ mode=validate／map／classify…
core-tree-capabilities
↓
共用規格包
優點入口少，共用資料結構容易集中。
代價單一 Skill 會逐漸變大，細項責任與維護界線較模糊。
判斷面向方案 1方案 2方案 3
同事直接呼叫細項較弱最清楚需記住 mode
AI 發現及選擇能力依賴父 Skill可由描述直接觸發先找到入口再判斷模式
規格獨立維護章節耦合責任界線明確集中但容易膨脹
跨語言重建實作可行每項均有獨立驗收契約可行但驗收範圍較大
治理成本最低需管理較多 Skill中等
我的建議：方案 2。 它直接落實您的核心要求：Skill 是公司可維護的業務規格與驗收來源，而 C#、Python 等只是可以替換的實作。增加的 Skill 數量可透過固定命名、共用術語與父 Skill 路由控制。
