# 4B 規則管理與版本化

## 範圍

本階段建立 Rule 1／Rule 2 的規則管理基礎，不執行 AML 修改或 Package 比較。正式核心負責預設規則、草稿驗證、人工發布、不可變版本、Checksum、共同規則與版本例外解析，以及衝突阻擋。

## 責任邊界

- `RuleSetValidator` 驗證規則範圍、步驟、順序與步驟參數。
- `RuleSetStore` 保存可修改草稿；只有具名人工操作者與核准證據可發布。
- 發布檔以 `RuleSetId` 與遞增版本另存，使用建立新檔語意，舊版不可覆寫。
- `RuleSetResolver` 先選擇每個規則集的最新已發布版本，再以 `StepId` 合併符合來源／目標版號的例外。
- 多個例外若對同一 `StepId` 定義不同內容，該步驟不產生有效規則且整體解析結果為 `Blocked`；其他獨立步驟仍會解析，互不重疊的例外可合併。
- 每次解析輸出所使用的規則集版本與 Checksum，供後續 Package 比較嘗試固定快照。

## 安全不變條件

AML 遞迴結構、CompareKey、可靠路徑配對、原始資料備份、目錄鎖、不可覆寫歷程、人工確認與 AI 權限限制不屬於可設定規則。AI 可提出建議，但不得建立、修改、發布或啟用規則。

## 後續銜接

Rule 1／Rule 2 執行能力必須以解析後的固定版本快照開始新的執行嘗試。變更規則只能發布新版本並建立新嘗試，不能回寫既有比較結果或 Package。
